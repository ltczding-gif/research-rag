## 3. 顺序与可交付迭代

### W0：固定合同与历史状态

先记录源 SHA、dirty 摘要、依赖/模型身份、数据 manifest 和本次运行范围。历史 RR1 0.8481 标为旧协议下暂定结果，等待严格重评；保留原报告和所有失败。评测协议升级后应另开结果版本，不覆盖旧榜单。

revision 2 在此处记录的是尚未执行的计划。revision 3 已按用户授权执行下列协议、修复与验收，具体结果见执行报告；质量门失败不记为通过。

### W1：gold、覆盖与缓存（E01/E02/E04）

这是任何新策略比较的前置迭代。先以已定位的 18 道低阈值提示题作为复核入口，再检查跨块证据、数值/否定/条件冲突与真实版本差异。

最小合同：

1. gold 保存独立于 chunker 的 file identity/hash、页文本 hash、半开 spans、最小充分证据内容；同一 alternative 多段必须共同满足，组内 alternative 为 OR，必须组之间为 AND。
2. `exact/adjudicated/weak_hint/unmapped` 显式区分。提示只能提出候选；弱提示未经裁定不直接计入主指标。exact 只代表文本对齐成功，gold 的科学充分性仍需核对。
3. 根据检索 Top-K 中区间并集计算覆盖，重叠区间去重；对 gold 定义的必需片段要求完整覆盖，并显式核对关键数值/否定/条件。旧任意交集指标只作为 `loose-hit` 诊断。
4. 发布独立版本的严格指标定义，写明增益、折扣、分母和聚合。统一冻结所有候选的可评价集合；同时报告预期 gold 总量、未裁定量及条件分母。不得候选各自删掉难映射 gold。
5. 保留 Top-K，同时增加固定上下文预算对照；预算单位/裁切规则事前冻结，不把不同 chunk 长度下的同 K 当等成本。
6. 完成态结果键绑定相关源码内容摘要及依赖/运行策略；Git SHA 与 dirty 内容分开记录。检索、映射、评分、切块、模型适配的改动进入对应层指纹；旧结果缺少必需指纹不得静默复用。初步止血可显式提高 revision，但不是完整验收。

验收：无关页码/章节不能变成已验证 gold；1 字符覆盖不能得充分证据满分；跨块并集可完整覆盖；真正 OR 替代仍可通过；不同集合仍阻断；不同实现旧完成缓存失效；仅改评分可保留验证过的检索轨迹和 embedding 缓存。

设计要求包括新版协议、裁定记录及负例测试；本轮实际完成的是代理裁定及独立代理复核，不能称为人类科学审阅。后者仍是尚未满足的 Beta 要求；不先启动大 sweep 再补标注。

### W2：可靠发布与来源生命周期（P01/P02/P03/P04/P09）

产品基于 main；可以在 W1 人工复核等待期间推进，执行上仍遵守单迭代工作区约束。

- 保留发现的全部附件及可信 parent/attachment identity、角色和 success/empty/missing/error 状态；不能过滤后重排 MAIN/SI。无法确定身份的旧笔记进入待确认状态。
- 采用完整 candidate generation：新集合与 generation 自有 ledger，验证后原子切 active manifest；失败保留旧 active 和错误详情。首次失败不能发布半成品。只保留必要的前一版回滚，不做热更新框架。
- manifest 绑定源集合、内容 hash、抽取器及依赖版本、chunker 参数、embedding provider/model/revision/dimensions、距离类型和 schema。查询检查契约；同维度换模型同样阻断。
- builder 的错误/部分成功退出码、构建入口和 index_status 语义一致；保留 notes-only 安装。
- 将删除/改名对账合并进完整快照：只发布本次有效来源集合，旧 generation 不参与查询。成功扫描前不得推断删除；空扫描、大范围撤回或不可用根目录不得自动清空 active。显式撤回后核验不可检索，保留回滚。
- 若仍选择增量写入，才需要额外稳定 note ID/tombstone；不要在全量 generation 上机械叠加两套生命周期方案。

验收：写入/embedding 异常与切换前中断保旧；空/缺失 SI 可见可重试；角色不漂移；配置变化正确失效；重复构建不重复；改名无双份 active；确认撤回不可查；根目录失联不误删；错误不能误报 ready。

### W3：溯源与查询范围（P05/P08）

最小移植 IR 及必要 helper/schema/test；固定抽取参数并声明索引迁移。保留 content/metadata/distance，新增 evidence 对象；复用现有 IR spans/邻接，不再造内部模型。

quote 必须能从该 generation 页文本准确回读；跨页引用分段，页码 0-based、展示 +1；哈希版本不符明确失败。接入 IR 邻接 ID，避免旧 `_chunk_` 推导失效。

定义 parent+attachment/source_type 的 AND 合同；冲突参数明确报错。HTTP/共享核心不得静默丢条件；MCP 添加最小可选附件/MAIN/SI 过滤入口并保持旧调用兼容。任意 basename 不能当作稳定附件身份。

验收：真实 MAIN/SI、跨页、同名附件、内容变更、上下文邻接、parent+SI 实际数据库过滤和 MCP 返回均核验。

### W4：最小策略修复与测量（E03/E05/P06）

依赖 W1；服务全链路对照另依赖 W3。首先过滤 BM25 零证据候选，空稀疏分支回退 dense。不用 dense-top1 保护替代零分过滤。

笔记主对照从既有 section/claim 中预先选定覆盖充分的一条，不按验收分数反选。记录每篇非空条目、backlink、路由为空与 fallback。reviewer-only 留作诊断，保留 S1 等退步结果，不预设笔记路线必胜。

初轮只对照 dense PDF、修正 hybrid PDF、覆盖合格的笔记辅助 PDF；固定模型、chunker、scope、数据/gold 与预算。先用新版指标给旧轨迹重新计基线，再一次只改一个策略因素。

已保存 hybrid-off/RR1 排名，但重评分前必须确认 ID→chunk→span 的原版本联接。资料齐全时离线重评；不齐全只重算所需阶段。禁止把本次历史统计当成严格重评结果。

计时分别记录 query_embedding/retrieval/rerank/serialization/total，并区分冷启动、首次查询、重复查询。文档矩阵预构建是小型性能改动，应先有测量，再验证排名容差不变。服务与评测使用同一 dense 内核、相同 index/配置时核对输出 parity；不同后端不强求逐项排序相同。

验收：零命中及不足 K 的稀疏分支、ID 改名、note 空路由、不同题组变化、真实 MCP 总时延；历史 54 倍仅注明旧核耗时比，不用作体验承诺。

### W5：笔记检索表示（P07）

这是独立迭代，不与 W1 更换 gold 同时作为一个效果变量。保留完整 note 实体，增加最小按节检索单元并回链到 note/source；记录实际模型输入范围和截断状态。

验收：尾部专属条件、否定结论、中英文混合笔记能够参与检索；get_note 全文仍可读。是否成为默认由同协议对照决定，不承诺拆得更细一定更好。

### W6：候选发布验收

产品发布依赖 W2/W3 及所宣称能力的验收；新策略默认值还依赖 W1/W4。若发布保持 dense，可用独立且人工核验的真实题集验收产品，不要求先修复全部历史 sweep。本轮题集只有代理编写及独立代理复核，human_reviewed=false；此项人工要求尚未满足，不能升级 Beta。

MCP 只检索；答案支持/拒答另固定客户端、模型及提示词评价。完成全新安装、原有回归、真实 PDF→MCP、版本/回滚和逐题失败记录。任何引用错误、源身份错误或数据安全门未过，继续 Alpha。

### W7：HTTP 日志（P10，按使用场景安排）

验收：不同 session、相同幂等键、追加动作和中途崩溃恢复；未做则不承诺并发日志可靠。
