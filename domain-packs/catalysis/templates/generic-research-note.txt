本模板仅在没有任何专用模板能明显更好匹配时使用。
默认 `_universal_rules.txt 与 _domain_quality_rules.txt` 已加载。本文件只定义正文结构，不重设计 note frontmatter。
正文默认使用中文；当能提高精度时，可保留必要的英文技术术语、方法标签和框架名称（括号内）。
如果文档内部明显是混合体，先按 section / 页码 / 附录把内容拆成事实层、解释层、方法层、背景层和补充层，再决定怎么写；不要把所有内容压成一个平均化摘要。
generic 只能承接真正难以专门化的残余部分和跨域缝合部分，不能拿来掩盖已经足够清晰的专用路由。
如果后续拿到更多上下文后，专用模板变得明显更合适，应优先重新路由，而不是在 generic 里用补丁式加长来硬撑。

## 使用边界

本模板是 broad、mixed、真正跨领域文档的兜底模板。
只要匹配关系清楚，就应优先使用专用模板，而不是停留在 generic fallback。

适用场景：
- 文档混合了多类证据，但没有一种模板家族明显占主导
- 笔记对象本身带有 exploratory、cross-domain 或 unusually hybrid 的性质
- 文档有保存价值，但其内部结构无法自然映射到 electrocatalysis、thermocatalysis、review、methods、dissertation 或 foundational-theory 合同
- 文档可能同时包含 primary material、secondary synthesis、commentary、方法说明、案例片段或附录线索，但没有任何单一层级足以单独接管整份笔记
- 某些段落能明显映射到专用模板，但整体仍由多种证据类型拼接而成，generic 只负责承接剩余混合部分

不适用场景：
- 明确的 review 或 perspective
- dissertation 或 thesis
- methods 或 materials-synthesis 论文
- theory paper
- 以性能主张为核心的实验论文
- 已经出现可稳定识别的系统综述（systematic review）特征，例如明确问题、预设检索、纳排标准、风险评估和系统综合
- 文档主体其实是单一方法、单一系统、单一理论框架或单一实验体系，只是当前上下文还没读全

如果适配关系存在歧义，要在边界 section 明确写出来，而不是假装本模板就是最优选择。
如果某一段或某一章已经足够像专用模板，就要在边界里点名“为何仍留在 generic”以及“未来更适合迁移到哪个模板”。

## 开篇摘要

不要为这一段额外加标题。
写一个简洁但高信息密度的摘要段，覆盖：
- 这是什么类型的文档
- 它的中心问题或核心贡献
- 它主要依赖的路径、方法或证据类型
- 最重要的结论
- 尽管不适合专用模板，但为什么仍值得保留这份笔记

## 文献基本信息

本节保持简洁、可读、适合人工检索。
必须包含：
- 推荐保存文件名
- 标题
- 期刊与年份
- DOI

规则：
- `推荐保存文件名` 不能省略
- 不要只是重复 PDF 原文件名
- 命名应帮助人工快速识别文档类型、核心主题和年份
- 不要因为 generic 就退化成“来源名 + review_note”；generic 仍然要给出有信息量的归档名。
- `推荐保存文件名` 仍必须遵循共享规则中的统一骨架：`年份-期刊或来源缩写-作者主线-核心主题-问题类型-关键框架或路径-贡献焦点_review_note.md`
- generic 不是命名自由区；即使文档很混合，也要尽量把“主题 / 问题类型 / 关键路径 / 贡献焦点”四个槽位稳定填出来。
- 若 DOI 缺失，写 `原文未提及 DOI`

## 文档类型与边界（Document Type / Boundary）

说明这份来源最像哪一类文档。
需要解释：
- 它最接近哪种 genre
- 哪一类证据占主导
- 为什么没有任何专用模板能自然覆盖
- 这种不匹配主要是结构问题、主题问题，还是混合证据类型导致
- 如果有一个差点可用的备选模板，也要简要点名
- 先判断哪些段落是原始证据，哪些是作者综合，哪些只是背景铺垫、术语解释或过渡说明
- 如果证据层次明显不同，要把它们分层写出来，不要把一手数据、二手综述和作者意见混成同一档
- 如果文档既有事实段落又有评论段落，边界说明要明确哪部分是事实性信息，哪部分只是作者判断或场景化解释
- 当备选模板只差一点就能接住时，说明“差在哪一点”；如果未来补到更多上下文就能稳定迁移，也要把目标模板写清楚
- 如果后续发现文档真正属于 review / perspective / methods / dissertation / theory / performance 中的任一类，应在笔记里留下可复核的重路由理由，而不是继续硬留在 generic

这一节要把 routing logic 写明，而不是含糊带过。

## 重新路由触发条件（Re-routing Triggers）

只要出现下面任一情况，就要主动重新判断是否应该离开 generic：
- 新增上下文表明该文档其实有稳定主导类型，例如 review、perspective、methods、dissertation、theory 或 performance paper
- 某一类证据在全文中反复出现并明显压过其他内容，generic 只剩下很薄的一层过渡说明
- 你为了让 generic 成立，开始依赖大量解释性补写、猜测性连接或人工缝合
- 文档后半段比前半段更像专用模板，说明当前路由判断可能只覆盖了局部
- 后续上下文足以把“混合”收敛成“主导 + 次要”，这时应迁往更专的模板，generic 只保留残余材料
- 一旦识别出可系统化复用的写作套路、方法结构或证据结构，也要重新评估是否应迁入专用模板，而不是长期停在兜底层

## 核心问题（Main Question）

写清这份文档真正处理的具体问题、缺口或目标。
表述要尽量精确。
如果文档本身比较发散，也要说明它真正贯穿全文的主线是什么。
能锚到 `[p.X]` 就尽量锚定。

## 主导证据类型（Dominant Evidence Type）

指出这份来源主要依赖哪类证据，例如：
- 实验
- operando characterization
- theory
- simulation
- benchmarking
- case comparison
- literature synthesis
- dataset analysis

随后解释：
- 这种证据在本文里最擅长证明什么
- 它单独不能证明什么
- 这份文档是建立在一个强单柱上，还是建立在多个较弱证据柱的组合上
- 证据权重应当分层：直接原始数据 / 一手观察 > 多来源综合 / 系统综述 > 单篇研究的解释性段落 > 评论 / 观点 / 背景说明 > 例子、类比和经验性断言
- 每个核心结论都尽量标明它是“直接证据”“间接支持”还是“作者推断”，不要让不同层级的材料在笔记里被压扁成同一种确定性
- 如果证据之间存在冲突，保留冲突本身和冲突来源，不要为了顺滑而强行平均化
- 若证据只覆盖局部条件，要明确写出适用边界、对象范围、样本范围和前提条件，避免把局部观察写成普遍规律
- 当来源同时包含 primary material 和 secondary synthesis 时，要优先让 primary material 承担事实锚点，让 secondary material 负责语境、对比和解释

## 证据层级与混合处理（Evidence Hierarchy / Mixed Evidence）

当一份文档把多种证据类型放在一起时，笔记必须做分层处理：
- 原始数据、图表、实验结果、案例材料或方程是事实锚点，优先用于支撑结论
- 作者的综合、讨论、评论和延伸判断可以用于解释，但不能被写成和原始证据同等级的事实
- 文献综述、背景铺垫和术语定义可以提供上下文，但除非其本身就是研究目标，否则不应承担最强结论
- 如果某些段落只是在“说法上更强”，而不是“证据上更强”，要把这种差异写出来
- 如果文档只提供单点证据或单案例证据，要明确降权，不要写成普遍适用
- 如果全文没有足够一致的证据链，就用“暂定”“原文未明确支持”“基于上下文推断”来标识，而不是硬给确定结论

## 核心内容（Core Content）

按照文档自身的内部逻辑总结主体内容。
尽量覆盖：
- 问题情境
- 研究对象或系统
- 核心方法或路径
- 主要结果
- 用朴素语言写出的最强 claim
- 对每个 major point，优先按“主张 → 证据 → 解释 → 仍不能证明什么”的顺序写
- 如果文档是跨章节拼接型或多材料拼接型，就按 section 分块总结，但每块都要标明它在整体中的角色
- 如果某段只是背景或方法过渡，不要把它抬成核心贡献；它更适合放在路由说明或边界说明里
- 如果原文把结果和解释混写，笔记里要尽量拆开，避免把解释误写成观察

规则：
- 定量数据保留 `value + unit + condition`
- 不要只列 figure number 而不解释它证明了什么
- 如果文档本质上是 negative、methodological 或 conceptual 的，要直接说明，不要硬套 performance-style summary

## 最强证据或论证（Strongest Evidence or Arguments）

优先记录最有支撑力的点。
对每个 major point，都要写：
- 正在被证明或被主张的是什么
- 什么证据在支撑它
- 这些证据为什么有说服力
- 它们仍然不能证明什么

证据可以来自：
- 图
- 对照
- 比较
- 数值趋势
- 方程
- 案例对比
- 基于原文的综合归纳
- 还要写出这些证据为什么比其他材料更强：是更直接、更可重复、更有对照，还是更能覆盖关键条件
- 如果是 literature synthesis、case comparison 或 benchmarking，要点明综合是建立在多少来源、什么比较维度和什么边界条件上，而不是只写最终判断
- 若证据强度不一，优先写强证据，再把弱证据作为补充，不要把弱证据和强证据并列成同一权重
- 对于看似漂亮但只来自单一来源、单一实验、单一案例的论证，要明确写出其局限，不要用语气把它抬成定论

若存在机理性或因果性推理，要沿用 shared depth citation logic，不要把它压扁成一句话。

## 最可复用的 takeaway（Most Reusable Takeaways）

提取那些可以迁移到这篇来源之外的内容。
可复用内容的类型可以包括：
- mechanisms
- diagnostic patterns
- experimental knobs
- failure modes
- decision rules
- scope boundaries
- literature search terms
- 诊断性标准、筛选标准、比较框架、命名方式、观察顺序、失败征兆和边界条件也都属于高价值可复用内容
- 对每一个 takeaway，都尽量写清适用范围、失效条件，以及它更接近硬结论、实践启发，还是仍偏暂定的 pattern
- 如果 takeaway 只能在原文那套系统里成立，要明确标成 narrow reuse，不要把局部规则伪装成通用原则
- 尽量保留可检索的关键词、对比项和决策句式，方便后续跨文档重用和再次检索

对每一个 takeaway，都要写清：
- 什么内容是可复用的
- 在什么边界内仍可复用
- 它属于硬结论、实践启发，还是仍偏暂定的 pattern

## 局限与开放问题（Limits / Open Questions）

诚实写出这篇来源的边界。
包括：
- 缺失的对照
- 薄弱点
- 过窄的 scope
- 未闭合的机理
- 含混的定义
- 论证超出证据支撑范围的位置

如果有重大问题没有说清，就写 `原文未提及` 或 `原文未明确讨论`。
- 区分三种不确定：原文未说、原文说得不够、以及笔记只能推断；不要把这三者混在一起
- 对冲突证据、弱对照、单样本、单案例、过窄样本都要标出来；如果只是作者主张而非证据支持，也要降权
- 当多个来源互相矛盾时，保留分歧本身和分歧来源，不要为了整洁强行合并
- 如果结论只在特定条件或特定对象上成立，要把这些条件写成显式边界，而不是藏在句子后半段

## 审稿人视角（Reviewer Lens）

紧凑回答这份笔记对以下任务是否有用：
- taxonomy tagging
- literature mapping
- method adoption
- mechanism tracing
- follow-up search

同时回答：
- 它是否有清晰的主导证据基础
- 它的内容能否超出单一体系复用
- 它的主要作用更偏 descriptive、persuasive，还是 genuinely evidentiary
- 如果将来拿到更多上下文，是否可能更适合被重新路由到某个专用模板
- 这份笔记是否已经把事实、解释和推断分开，如果还没有，说明 generic 还在替代一个更专门的模板职责
- 如果文档实际上已呈现出清晰的 review / methods / theory / dissertation / performance 轮廓，要明确写出重路由信号，而不是只说“仍可保留”
- 当主导证据类型在全文里高度一致时，generic 的角色应缩小为兜底说明；如果 generic 还在承担主体总结，说明路由判断可能过宽
- 如果后续上下文能明显提升路由确定性，要回写这个判断，不要沿用当前的模糊边界

## 主观打分

使用简洁数值评分，并给一句明确理由。
推荐范围：1-5。

必需维度：
- 证据强度（1-5）
- 复用价值（1-5）
- 模板适配度（1-5）

评分规则：
- 当文档过窄、过于推测、控制不足或很难复用时，分数应更低
- 当文档有清晰对照、强比较、明确边界且洞见能迁移出单一体系时，分数应更高
- 评分可以简洁，但理由必须明确
- 评分时要拆开看三件事：内容价值、证据质量、generic 适配性；不要把三者揉成一个印象分
- 如果文档只是松散堆砌、事实和意见难分，适配度分数应主动下调，即使主题本身很有意思
- 如果混合证据很多但边界非常清楚，generic 适配度可以高于平均水平；反过来，如果边界不清，即使内容不错也要保守打分

## 核心结论总结

用一个结尾段说明：
- 这份来源为什么值得保留
- 它最强的可复用内容是什么
- 它最主要的边界或弱点是什么
- 如果后续拿到更多上下文，是否值得重新路由到某个专用模板
- 最后一两句最好直接落到“generic 是否仍然合适”以及“若未来补齐上下文，最可能迁往哪个模板”
- 不要让结尾只剩态度判断；要把可复用价值、局限和路由可能性一起收束

## 写作规则

- 笔记要保持 self-contained，即使读者手边没有原文也能读懂。
- 优先 evidence-backed summary，而不是穷尽式改写。
- 每个 section 内部先写最有决策价值的信息。
- 避免空泛 filler；每个 section 至少要给出一个具体事实、比较或推论。
- 保持紧凑，但不要让 generic fallback 变成浅层摘要。
- 一旦专用模板适配关系清楚，就要承认专用模板优先。
- 把原文事实、作者主张、以及笔记推断明确分开；必要时直接使用“原文明确 / 原文暗示 / 笔记推断”这样的措辞
- 如果只能给出弱结论，就要连同不确定来源一起写出来，不要伪装成强结论
- 对冲突材料不要强行揉成一致说法；应该保留分歧、说明差异，并标注它们各自来自哪里
- 对于看起来“像结论但其实只是语境”的句子，宁可降级到边界或背景，也不要为了完整性把它写进核心结论

## 执行约束

本模板完全受 `_universal_rules.txt 与 _domain_quality_rules.txt` 约束；所有 shared rules 无条件生效。
generic 模板可以更紧凑，但不能含糊。
所有事实性表述都必须只基于当前附加文档。
信息缺失时，写 `原文未提及` 或 `原文未明确讨论`。
generic 不是信息垃圾桶；它的任务是把难以专门化的内容处理得更可用，而不是把路由不确定性藏起来。
当 review 证据足够强时，应把“仍留在 generic”的理由写成可复核的路由判断，而不是依赖模糊措辞继续拖延。
